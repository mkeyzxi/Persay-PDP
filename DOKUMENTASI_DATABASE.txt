1. GAMBARAN UMUM SISTEM
================================================================================

Sistem Prisay-PDP merupakan aplikasi manajemen proyek terintegrasi yang 
mengelola data proyek konstruksi, pengeluaran material, dan dokumen-dokumen 
terkait. Sistem ini mengintegrasikan data dari SAP dan memiliki empat 
departemen utama yang menggunakan aplikasi ini:

- Admin       : Mengelola pengguna dan konfigurasi sistem
- Logistik    : Menginput data header proyek dan pengeluaran material
- Konstruksi  : Menginput data pelaksanaan kontrak dan progress proyek
- Akuntansi   : Mengelola kategorisasi PDP dan tindak lanjut

Database menggunakan MySQL/MariaDB dengan Laravel Eloquent ORM.

4.2 DETAIL RELASI
-----------------

A. users → projects (One-to-Many)
   - Kolom: projects.created_by → users.id
   - Constraint: ON DELETE SET NULL
   - Keterangan: Satu user dapat membuat banyak proyek

B. users → sessions (One-to-Many)
   - Kolom: sessions.user_id → users.id
   - Keterangan: Satu user dapat memiliki banyak sesi

C. projects → project_wbs_logs (One-to-Many)
   - Kolom: project_wbs_logs.project_id → projects.id
   - Constraint: ON DELETE CASCADE
   - Keterangan: Satu proyek dapat memiliki banyak log WBS

D. users → project_wbs_logs (One-to-Many)
   - Kolom: project_wbs_logs.set_by → users.id
   - Constraint: ON DELETE RESTRICT
   - Keterangan: Setiap log WBS dicatat oleh satu user

E. projects → project_documents (One-to-Many)
   - Kolom: project_documents.project_id → projects.id
   - Constraint: ON DELETE CASCADE
   - Keterangan: Satu proyek dapat memiliki banyak dokumen

F. users → project_documents (One-to-Many)
   - Kolom: project_documents.uploaded_by → users.id
   - Constraint: ON DELETE SET NULL
   - Keterangan: Dokumen mengetahui siapa yang upload

G. projects → material_issues (One-to-Many)
   - Kolom: material_issues.project_id → projects.id
   - Constraint: ON DELETE CASCADE
   - Keterangan: Satu proyek dapat memiliki banyak transaksi material

H. users → material_issues (One-to-Many)
   - Kolom: material_issues.created_by → users.id
   - Constraint: ON DELETE SET NULL
   - Keterangan: Transaksi material dicatat oleh user

I. material_issues → material_issues_items (One-to-Many)
   - Kolom: material_issues_items.material_issue_id → material_issues.id
   - Constraint: ON DELETE CASCADE
   - Keterangan: Satu header transaksi memiliki banyak item

J. materials → material_issues_items (One-to-Many)
   - Kolom: material_issues_items.material_id → materials.id
   - Constraint: ON DELETE RESTRICT
   - Keterangan: Satu material dapat digunakan di banyak transaksi

K. projects → material_issues_items (HasManyThrough)
   - Melalui: material_issues
   - Keterangan: Akses langsung dari proyek ke detail item material

5.1 ALUR PROSES UTAMA
---------------------

TAHAP 1: INISIASI PROYEK (Departemen Logistik)
----------------------------------------------
1. Data proyek diimport dari SAP atau diinput manual
2. Kolom yang diisi:
   - spk_number (wajib, unique)
   - wbs_number
   - project_name
   - vendor_name
   - unit_code
   - fiscal_year
3. Status awal: DRAFT

TAHAP 2: PELENGKAPAN DATA KONTRAK (Departemen Konstruksi)
---------------------------------------------------------
1. Konstruksi melengkapi data kontrak:
   - contract_number
   - contract_value
   - contract_start_date
   - contract_end_date
   - target_completion_date
   - location
2. Update progress secara berkala:
   - proggress_percent
3. Input tanggal milestone:
   - bastp_date (BAST Pendahuluan)
   - slo_date (Sertifikat Laik Operasi)
4. Upload dokumen proyek ke project_documents

TAHAP 3: PENGELUARAN MATERIAL (Departemen Logistik)
---------------------------------------------------
1. Import data Material Issue dari SAP:
   - Header: material_issues (sap_doc_no, posting_date)
   - Detail: material_issues_items (quantity_sap, val_currency)
2. Master material dikelola di tabel materials
3. Konstruksi melengkapi data instalasi:
   - quantity_installed
   - asset_number
   - asset_number_date

TAHAP 4: MONITORING PDP (Departemen Akuntansi)
----------------------------------------------
1. Akuntansi menganalisis dan mengkategorikan proyek:
   - category
   - pdp_category
   - follow_up_code
   - constraint_note
2. Mengupdate status proyek:
   - OPEN: Proyek masih berjalan
   - CLOSED: Proyek selesai
   - CANCELED: Proyek dibatalkan

6.2 POTENSI MASALAH TERIDENTIFIKASI
-----------------------------------

MASALAH #1: Duplikasi WBS Number
--------------------------------
Lokasi: projects.wbs_number dan material_issues_items.wbs_element
Deskripsi: WBS Element disimpan di dua tempat berbeda
Risiko: Inkonsistensi data jika WBS diubah di salah satu tempat
Tingkat: MEDIUM

MASALAH #2: Tidak Ada Unique Constraint pada sap_doc_no
-------------------------------------------------------
Lokasi: material_issues.sap_doc_no
Deskripsi: Nomor dokumen SAP seharusnya unique per proyek
Risiko: Duplikasi data transaksi material
Tingkat: HIGH

MASALAH #3: Typo pada Nama Kolom
--------------------------------
Lokasi: projects.proggress_percent
Deskripsi: Penulisan "proggress" seharusnya "progress"
Risiko: Kesulitan maintenance dan query
Tingkat: LOW

MASALAH #4: Duplikasi Field Category
------------------------------------
Lokasi: projects.category dan projects.pdp_category
Deskripsi: Kedua kolom menyimpan value yang sama (D1.1 - D5)
Risiko: Redundansi dan potensi inkonsistensi
Tingkat: MEDIUM (Perlu klarifikasi apakah berbeda fungsi)

MASALAH #5: Tidak Ada Soft Delete
---------------------------------
Lokasi: Semua tabel utama
Deskripsi: Tidak ada mekanisme soft delete (deleted_at)
Risiko: Data yang dihapus tidak dapat di-recover, audit trail hilang
Tingkat: MEDIUM

MASALAH #6: Relasi material() dan issue() Duplikat
--------------------------------------------------
Lokasi: MaterialIssuesItems model
Deskripsi: Ada dua method yang sama: materialIssue() dan issue()
Risiko: Kebingungan dalam penggunaan dan maintenance
Tingkat: LOW

MASALAH #7: Bug pada Migration Down Method
------------------------------------------
Lokasi: 2026_01_26_174448_add_asset_number_date_to_material_issues_items
Deskripsi: Method down() menggunakan addColumn bukan dropColumn
Risiko: Rollback migration akan gagal/salah
Tingkat: HIGH

LAMPIRAN: QUERY VERIFIKASI
================================================================================

-- Cek proyek dengan material issue tertinggi
SELECT p.spk_number, p.project_name, COUNT(mi.id) as total_issues
FROM projects p
LEFT JOIN material_issues mi ON p.id = mi.project_id
GROUP BY p.id
ORDER BY total_issues DESC
LIMIT 10;

-- Cek total nilai pengeluaran per proyek
SELECT p.spk_number, p.contract_value, 
       SUM(mii.val_currency) as total_expense,
       p.contract_value - SUM(mii.val_currency) as remaining
FROM projects p
LEFT JOIN material_issues mi ON p.id = mi.project_id
LEFT JOIN material_issues_items mii ON mi.id = mii.material_issue_id
GROUP BY p.id;

-- Cek material yang paling sering digunakan
SELECT m.sap_material_code, m.material_description, 
       COUNT(mii.id) as usage_count,
       SUM(mii.quantity_sap) as total_qty
FROM materials m
LEFT JOIN material_issues_items mii ON m.id = mii.material_id
GROUP BY m.id
ORDER BY usage_count DESC
LIMIT 10;
